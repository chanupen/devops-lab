```text
Labs 2, 3 and 5, plus the policy stack.
Worktree: git worktree add ../devops-lab-wt-labs -b feat/labs-2-3-5 origin/main

Follow labs/README.md. All three are needs: lab, modes [local] for now,
designed so cloud only needs an overlay (ECR instead of Zot). Each lab
works only in its own namespaces (lab02-*, lab03-*, lab05-*) and cluster
objects labelled lab.devops/lab=<id>; reset.sh removes exactly those.
Extra tools (Trivy, Skopeo, Sloth, kyverno CLI) run as digest-pinned
images through rootless Podman, not host installs.

Lab registry: Zot's writable lab/ namespace, separate from the cache,
published on 127.0.0.1 only. LAB_REGISTRY_PUSH=127.0.0.1:5000/lab from
the host, LAB_REGISTRY_PULL=lab-zot:5000/lab in the cluster. lab doctor
checks the push path (opens an upload and cancels it).

Lab 2: build, scan and promote by retagging.
- A small app with a base image that has a known HIGH/CRITICAL CVE on
  purpose. Steps: build with rootless podman; push as dev; scan with
  Trivy and fix by moving to a patched base; deploy to lab02-dev by
  digest; promote to lab02-prod by copying the same digest with skopeo,
  no rebuild; prove prod runs the digest that was scanned.

Lab 3: SLO and burn-rate alerts for the sample app.
- SLI from metrics obs already scrapes, recording rules with
  `or vector(0)` so the ratio exists before the first error; 99.5% /
  30d SLO; multiwindow multi-burn-rate alerts as a PrometheusRule.
- README gives the Google SRE workbook table correctly: 14.4x 1h/5m
  page, 6x 6h/30m page, 1x 3d/6h ticket; the lab uses shorter windows
  and explains why. Inject errors with a Job (podinfo returns 500s),
  watch the page fire in Alertmanager (port-forward + curl; Alertmanager
  rejects kubectl create --raw), then generate the same rules with
  Sloth's CLI and compare.

Lab 5: Kyverno policy that blocks images without a digest.
- policy stack: Kyverno via Argo CD, pinned, small local resources,
  baseline Pod Security policies in Audit mode only. ignoreDifferences
  on CRD labels/annotations and ServerSideApply=true (the CRDs are too
  big for client-side apply and otherwise stay OutOfSync).
- compat row for Kyverno with Stack: policy. If upstream states a lower
  max than its CI tests, use StatedMaxK8s (doctor warns).
- Teach ValidatingPolicy (CEL), not the deprecated ClusterPolicy; one
  README paragraph on ClusterPolicy as the older form. Steps: Enforce
  policy scoped to lab05-*; a tag-only Pod denied (server-side dry run);
  a digest Pod allowed; a PolicyException for one Deployment matched by
  ownerReferences (not a label anyone can copy); PolicyReports;
  `kyverno test` offline.

Testing: e2e on the main cluster, inside the labs' namespaces only;
`lab up --stacks policy` once. Work through each lab as a learner. PR
gives per-lab time and memory added.
```
